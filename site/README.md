# Organiya production website

This is the independent Option O static website for Organiya's upcoming Spicenza snack range in India. It uses ordinary HTML/CSS/JavaScript generated by a small Node build. No Astro, CMS, customer accounts, cart, database or payment service is required.

The repository root retains the previous website intact. **Do not delete or repurpose those files.** The archive tag `archive/pre-option-o-2026-11-11` identifies its exact source. The `main` branch and its GitHub Pages deployment remain the legacy fallback. Current production work is on `codex/organiya-launch` under `site/`.

## Build and test

Use Node 22 or newer:

```sh
cd site
npm ci
npm run validate
npm run build
npm test
```

`npm run preview` serves `dist/` at http://127.0.0.1:4176. Browser tests cover all route types at 320/390/768/1440px, all product galleries, search, keyboard behavior, inquiry context, no-JS content, old-route redirects, missing pages, metadata and automated WCAG accessibility checks. No email is sent by these tests.

Cloudflare Pages build settings: no framework, root directory `site`, command `npm ci && npm run build`, output `dist`, production branch `codex/organiya-launch`. Use the recorded deployment configuration in `docs/LAUNCH-RECORD.md` as the source of actual hosting state. Publish only `dist/`; it excludes the old website, review launcher, source docs, tests and unused images.

## Content changes through Codex

| Change | Edit |
| --- | --- |
| Identity, email, navigation and phase notices | `content/site.json` |
| Home, Story, contact introductions and family occasions | `content/pages.json` |
| Product copy, card images, galleries and future SKU fields | `content/products.json` |
| Original approved illustrations / logos | `assets/` |
| Shared layout and page compositions | `src/components.js`, `src/pages/` |
| Option O colours / shared UI | `styles/food.css`, `styles/production.css` |

The build generates image dimensions and responsive widths from actual assets. It produces hashed image filenames, static HTML, metadata, sitemap, robots, security headers and redirects. Keep card images 4:5; galleries follow actual image proportions and do not letterbox.

Inquiries use `mailto:` links to the monitored public address. A product-specific email draft opens in the visitor's email app; the visitor sends it there. The site does not display a fake sent confirmation, store form data, or enrol visitors in marketing. No demo forms are shipped.

Current launch is **upcoming**: no SKU, price, availability, label data, licence claim or nutrition number is invented. The current validation deliberately prevents an accidental change into commerce. After licensing and product finalisation, implement the announced-product validator/display with the actual approved fields and media, then review and publish a content release. Ordering remains a separately scoped change. Do not change the current slug of Crunch Mix just to change its display name.

A future Decap UI can map these JSON files; it needs authentication and an editorial release workflow. Astro could replace the small build layer if useful. Neither is needed to keep this site online.

Before any release: validate → build → test → GitHub checks → preview → deploy → smoke. Preserve rollback and email/DNS records. Never publish credentials, private formulation/lab evidence, inquiry records or internal diagnostics.
